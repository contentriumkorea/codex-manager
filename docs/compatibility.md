# 호환성 검증

2026-10-13, Codex Manager 0.10.0은 이 컴퓨터의 앱 내장 `codex-cli 0.162.0-alpha.17.2`로 격리 저장소의 병합·백업·가져오기·복원 확인·원본 정리 흐름을 검증했다. 앞선 2026-10-06 검증에서는 `0.160.0`을 사용했다. 별도 설치 경로의 `0.149.0`은 새로운 대화의 world_state를 같은 방식으로 해석하지 못하므로 변경에 사용하지 않는다.

- 프로젝트 생성·조회·루트 변경·삭제: 격리 저장소 검증.
- 상위 폴더에서 여러 백업 검색, 기존 프로젝트에 병합, 중복 대화 유지, 병합 중단 후 재개를 격리 저장소에서 검증했다. 0.9.0에서 중단된 가져오기도 기존 프로젝트를 다시 사용한다.
- 완전 삭제는 프로젝트·대화와 선택한 작업 파일만 대상으로 하며 공유·연결·보호 경로와 이후 변경된 파일을 차단한다. 복구 가능 삭제는 자동 로컬 보관 위치를 사용한다.
- 대화 프로젝트 배정: 격리 저장소와 재조회 검증.
- 기존 대화 경로 변경: resume + settings/update 후 별도 서버 재시작 재조회 검증. 대화를 삭제·재등록하지 않는다.
- 원시 대화 가져오기: 파생 사본의 session_meta, 마지막 활성 turn_context, 마지막 로컬 환경 cwd를 새 경로로 설정한다. 이전 대화 문장과 역사적 경로를 일괄 치환하지 않는다.
- 실제 test b: 대화 1개, 대화 턴 3개, 작업 파일 12개를 독립 저장소로 복원했다. 원본은 유지했다.
- test a: `.codex-build/node_modules`가 연결 폴더여서 자동 따라가기·삭제를 차단한다.
- thread/delete: 활성 대화의 저장 파일·목록 삭제를 격리 저장소에서 확인했다. 프로젝트 삭제는 파일과 대화를 삭제하지 않고 소속을 해제하는 동작을 확인했다.
- 원본 정리 중 부분 실패: 남은 대화를 보존하며 삭제된 대화·파일을 복구한다. 공식 project/list의 data·페이지 커서를 사용해 삭제 후 남은 UI 캐시와 실제 프로젝트를 구분한다. 프로젝트 생성·대화 등록의 응답 유실 후 재실행도 격리 앱 서버에서 확인한다.
- 별도 sqlite_home 설정, 초기화 실패한 서버 프로세스 정리, 손상된 설정, 분리된 외장 백업, 프로젝트 안의 verification.json/checksums.jsonl 파일을 포함한 백업을 회귀 테스트한다.
- Windows 기존 앱 서버 공유 연결: daemon/proxy lifecycle이 Unix 전용이므로 앱을 종료한 상태에서 공식 stdio 서버로 변경한다. 실행 중 전역 SQLite나 UI 설정을 직접 수정하지 않는다.
- 앱을 종료한 상태에서만 legacy 프로젝트 매핑과 선택·목록 캐시를 원자적으로 갱신한다. 다른 설정은 보존하고 이전 상태 파일을 로컬에 남긴다.
- 실제 계정으로 이어쓰기, 실제 두 번째 PC, 모바일 표시: 사용 환경 검수 필요. 백업별 이어쓰기 확인 절차는 프로그램에 구현했다. 자동 테스트의 성공 턴은 fixture 시뮬레이션이며 실제 계정 검증으로 보고하지 않는다.

Codex 업데이트 이후에는 이식과 원본 정리 테스트를 다시 수행해야 한다. 알 수 없는 실패는 원본 삭제를 중단한다.
