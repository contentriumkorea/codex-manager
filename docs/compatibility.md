# 호환성 검증

2026-11-02, 0.12.0의 저장소 간 전송과 기존 관리 작업은 이 컴퓨터에 설치된 Codex `0.166.0-alpha.5.1` 및 지원 최소 버전 `0.160.0` 앱 서버의 격리 저장소로 검증했다. 실제 사용자 대화와 작업 파일을 변경하는 시험은 하지 않았다.

- 서로 다른 두 저장소에서 프로젝트 전체·선택한 대화·파일의 이동과 복사, 기존 프로젝트 병합, 중단 후 재개를 검증했다. 한글·Unicode 이름의 두 작업 폴더를 사용하는 대화는 대상 파일 내용, 제목, 현재 작업 폴더와 보조 작업 폴더 연결 및 원본 정리를 확인했다.
- 대상에도 참조가 있는 공유 원본은 보존한다. 대화 ID 충돌, 미리보기 이후 원본 변경, 겹치는 저장소·폴더와 보호 경로는 전송을 차단한다. 256자 Unicode 프로젝트 표시 이름을 유지하고 제안된 폴더를 실제로 만들 수 있는지 확인했다.
- 완료된 저장소 간 전송에는 일반 되돌리기·Ctrl+Z를 제공하지 않는다. 중단된 작업은 작업 내역에서 재개한다. 이동한 대화의 복구 사본은 대상 드라이브에 남으며 위치와 크기를 작업 내역에 표시한다. 전송 중에는 임시 사본과 최종 파일이 함께 존재할 수 있다.
- Windows 경로의 슬래시·대소문자·확장 경로 표기만 다른 경우 같은 보조 작업 폴더로 비교한다. 실제로 추가되거나 바뀐 보조 작업 폴더는 되돌리기를 계속 차단한다.
- 전체 SQLite 목록과 명시적 소속, 여러 작업 폴더 및 이전 로컬 호스트 매핑을 읽는다. 폴더 이름이 비슷하다는 이유로 대화를 임의 배정하지 않는다.
- 프로젝트·대화 이름 변경, 이동·병합, 복구 가능 삭제·복원, 영구 삭제의 부분 완료 정리, 백업과 별도 저장소 가져오기, 폴더 이동과 원본 정리를 시험한다.
- 가져오기 중 대화 등록 직후 중단된 상태와 보관된 대화의 재개, 기존 프로젝트 연결 정리 중단 후 재개를 시험한다. 중단된 정리를 완료한 뒤에는 변경된 목록에서 다시 선택한다.
- 옮긴 파일이나 보조 작업 폴더가 이후 변경되면 되돌리기를 거부하고 현재 작업을 보존한다. 복사 중 취소되어 원본·연결이 그대로면 부분 출력은 보존하고 복구를 종료한다.
- 원시 대화는 새 사본의 현재 작업 경로만 바꾼다. 과거 대화 문장과 역사적 경로를 일괄 치환하지 않는다.
- 별도 `sqlite_home`, 알 수 없는 저장 형식, 정션·심볼릭 링크, 같은 ID 충돌과 공유 작업 폴더를 검사한다. 해석할 수 없는 형식에서는 쓰기를 중단한다.
- Codex 저장소·데이터베이스·Manager 설정 폴더는 프로젝트 이동·백업·파일 정리의 대상으로 사용하지 않는다.
- 외부 작업 폴더·첨부·다른 프로젝트의 자식 대화가 포함되어 의존성이 해결되지 않은 백업은 자동 가져오기를 차단한다. 해당 백업을 완전한 이식본으로 간주하여 원본을 삭제하지 않는다.
- 실제 Windows 창에서 프로젝트 조회, 이름 변경·복구, 파일 목록, 새 폴더 생성·복구와 작은 창 표시를 확인한다. 물리 키보드·마우스 입력에 의한 단축키와 드래그 시험은 수행하지 않았다.
- 실제 계정으로 다른 물리 PC에서 이어쓰기, 모바일 표시, Windows 10의 실제 실행과 여러 DPI·다중 모니터 조합은 별도 검수가 필요하다. 사용자 디스플레이 설정을 시험을 위해 바꾸지 않는다.

설치·업데이트·포터블·제거 및 공개 다운로드 검증 결과는 릴리스 점검 기록에서 구분한다. 빌드나 격리 시험만으로 실제 계정과 모바일 동기화까지 검증됐다고 보지 않는다. Codex 업데이트로 저장 형식이 바뀌면 이식과 원본 정리를 다시 확인해야 한다.

내보내기가 중단되면 새 임시 사본을 만들기 전에 소유권·내용·원본이 확인되는 이전 시도를 정리합니다. 변경·교체·미확인 항목은 자동 삭제하지 않으므로 안전 종료로 보존 위치를 확인해야 합니다. 필요한 최대 임시 용량과 드라이브 여유 공간의 정량 사전 검사는 제공하지 않습니다. 임시 사본·최종 파일·남겨진 복구 사본을 위한 여유 공간을 직접 확인하세요.


## 0.12.2 대화 분류 호환성

- 실제 프로젝트 소속과 표시용 소속을 분리한다. 명시된 native/기존 desktop 소속을 우선하며, 유일한 최장 작업 폴더 또는 부모 대화 관계만 표시용 근거로 사용한다. Windows 경로의 슬래시·대소문자·verbatim UNC와 폴더 경계를 정규화한다.
- 명시적인 프로젝트 없음, 다른 기기 연결, 없는 프로젝트, 같은 깊이의 여러 프로젝트와 순환 관계를 추측으로 연결하지 않는다. `has_user_event=false`만으로 일반 대화를 숨기거나 빈 대화로 분류하지 않는다.
- 하위 에이전트 및 guardian review는 내부 기록으로 기본 목록에서 숨기되 보관 여부와 별개로 취급한다. 내부 기록과 부모 의존성은 백업·전송에서 유지한다.
- 표시만 된 소속은 SQLite/desktop 설정에 기록하지 않는다. 같은 저장소의 프로젝트 작업은 필요한 연결을 확인하고 SDK로 기록한 뒤 진행하며, 확인 시 원래 소속·목록 revision·대화 ID를 재검증한다. 복구는 이후 작업부터 역순으로 수행한다. 삭제·병합 복구가 새 프로젝트 ID를 만들었으면 완료된 해당 대화 복구 journal의 ID만 인정한다.
- 이전 형식 프로젝트의 표시 전용 연결 확인은 먼저 프로젝트 이름 변경으로 native 연결을 갱신해야 한다. 불명확하거나 다른 기기인 자식 연결은 자동 작업을 중단하고 명시 선택을 요구한다. 일반 되돌리기를 지원하지 않는 저장소 간 전송 제한은 유지한다.
