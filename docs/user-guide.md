# Codex Manager

Windows에서 로컬 Codex 프로젝트, 대화, 작업 폴더를 함께 관리합니다. Python 설치 없이 `CodexManager.exe`를 실행할 수 있습니다.

v0.5.0부터 화이트·실버 바탕의 밝은 글래스모피즘 화면을 사용합니다. 프로젝트·대화의 선택은 옅은 블루로 표시하고, 파일 목록·대화 패널·메뉴·확인창·업데이트 화면의 색상과 여백을 통일했습니다. 기존 관리 기능과 단축키는 그대로 사용할 수 있습니다.

`CodexManager.exe`와 `_internal`이 들어 있는 **CodexManager 폴더 전체**를 보관하거나 다른 컴퓨터로 복사하세요. 외장하드나 D 드라이브에서 바로 실행할 수 있습니다. 다른 PC·모바일의 실제 계정 이어쓰기는 검수 대기입니다.

## 업데이트

시작할 때 GitHub의 최신 정식 배포를 백그라운드로 확인합니다. 새 버전이 있으면 업데이트 화면을 열고 미리 다운로드·검증합니다. 인터넷에 연결되지 않아도 프로그램을 사용할 수 있습니다.

왼쪽 **업데이트**에서 현재 버전, 최신 버전과 변경 내용을 볼 수 있습니다. **업데이트 확인**으로 다시 확인하거나 **프로그램을 시작할 때 업데이트 확인**을 끌 수 있습니다. 준비가 끝나면 **지금 업데이트**를 눌러 바로 설치·재시작합니다. 다운로드 중에 **업데이트 설치·재시작**을 눌러도 추가 클릭 없이 준비 직후 설치합니다. 진행 중인 백업·이동은 끝날 때까지 기다립니다. 다운로드 진행률과 현재 단계가 표시되며, 실패해도 창을 유지하고 **다시 시도**할 수 있습니다. 다운로드가 끊기면 한 번 자동 재시도하고, API 요청 한도 초과 시 공개 배포의 메타데이터를 확인합니다. 검증된 준비 파일은 같은 프로그램 위치에서 재사용합니다.

다운로드와 프로그램 파일별 SHA-256을 확인한 뒤 앱을 닫고 새 버전으로 실행합니다. 새 프로그램의 시작을 확인한 뒤 이전 프로그램 파일을 정리합니다. 시작에 실패하면 이전 프로그램 폴더로 복구합니다. 대화·프로젝트·작업 폴더·백업은 업데이트로 변경하지 않습니다. 기존 설정은 `%LOCALAPPDATA%/ProjectConversationManager`에 유지합니다.

프로그램 폴더 안의 사용자가 추가하거나 변경한 파일은 삭제하지 않고 같은 상위 폴더의 `.codex-manager-previous-...`에 남깁니다. 설치 결과는 설정 폴더의 `updates/last-result.json`에 기록됩니다. 읽기 전용 위치나 연결 폴더에서는 일반 쓰기 가능한 폴더에 프로그램을 준비하세요. 이전 `ProjectManager` 배포는 새 이름의 폴더를 별도로 풀어 실행하면 같은 설정을 사용합니다.

교체 중 정전 등으로 실행 경로가 사라졌다면 프로그램을 종료한 상태에서 설정 폴더 `updates` 안의 해당 `recover-*.cmd`를 실행하세요. 기록된 이전 프로그램 폴더를 복구합니다. 중단 기록이 있으면 업데이트 화면에도 복구 위치를 여는 버튼이 표시됩니다. 이미 끝난 업데이트를 다시 복구하지 않으며, 알 수 없거나 변경된 설치 폴더는 자동 덮어쓰지 않습니다.

## 시작

1. **모든 프로젝트**에서 이름·폴더 위치·대화 수·용량을 확인합니다.
2. 프로젝트를 두 번 클릭하거나 **열기**를 누르면 안의 파일과 폴더가 표시됩니다. 폴더는 두 번 클릭해 들어가고, 파일은 기본 프로그램으로 엽니다.
3. **←**, **↑**, 위쪽 **프로젝트**로 되돌아갑니다. 폴더가 여러 개면 주소 아래에서 선택합니다. 주소 입력란은 현재 프로젝트 안의 폴더로 이동할 때 사용합니다.
4. 오른쪽 **대화**에서 대화를 두 번 클릭해 읽습니다. **폴더 위치** 탭에서는 프로젝트 폴더를 확인합니다.
5. 상단 또는 프로젝트 우클릭 메뉴에서 **옮기기·합치기·백업 만들기**를 선택합니다. **이름 변경**은 프로젝트 표시 이름을 바꾸며 실제 폴더명은 유지합니다. 연결 폴더 변경은 **더 보기 → 프로젝트 설정**에서 합니다. 파일 탐색은 읽기 전용이며, 프로젝트 이동은 대화를 함께 처리하는 옮기기를 사용합니다.

## 이름 변경·대화 이동·삭제

- **프로젝트 이름 변경:** 프로젝트 우클릭 → 이름 변경, 또는 더 보기 → 이름 변경. 프로젝트 목록에 초점을 두고 F2를 눌러도 됩니다.
- **대화 제목 변경:** 오른쪽에서 대화 하나 선택 → 우클릭 → 제목 변경. F2 또는 대화 관리 메뉴에서도 가능합니다.
- **대화 여러 개 이동:** Ctrl·Shift로 대화 선택 → 대화 관리 → 프로젝트로 이동. 소속만 변경하며 대화 기록과 작업 파일 위치는 유지합니다. 파일도 함께 옮기려면 프로젝트의 옮기기·합치기를 사용하세요.
- **대화 삭제:** 선택한 대화를 우클릭 → 대화 삭제. 프로젝트와 작업 파일은 유지합니다. 연결된 자식 대화가 있으면 함께 삭제될 목록을 먼저 표시합니다.
- **프로젝트 삭제:** 프로젝트 우클릭 → 프로젝트 삭제. 확인창에 표시한 프로젝트와 대화를 삭제합니다. 실제 파일은 기본적으로 유지하며 **연결된 실제 작업 폴더와 파일도 삭제**를 선택한 경우에만 삭제합니다. 이 경우 복구 사본을 둘 폴더를 선택해야 하며, 다른 프로젝트·대화가 공유하는 폴더는 삭제하지 않습니다.
- **삭제 취소·복구:** 삭제 전에 대화 복구 사본을 자동 검증합니다. 삭제 후 **작업 복구 → 삭제 복구**에서 되살립니다. 파일까지 삭제한 경우 검증한 사본으로 파일도 복원합니다. 복구 사본은 자동으로 지우지 않으며, 사본이 있는 외장하드는 복구할 때 연결돼 있어야 합니다.

이름 변경·이동·삭제·복구는 Codex 앱을 완전히 종료한 상태에서 실행하세요. 재실행하면 반영된 목록을 확인할 수 있습니다. 분류할 대화에서도 여러 항목 선택 후 우클릭으로 이동·삭제할 수 있습니다. 백업 안의 대화는 조회만 가능합니다.

**외장하드에 보관:** 프로젝트 선택 → 백업 만들기 → 외장하드의 폴더 선택. 백업을 마치면 백업 화면에서 결과를 확인합니다.

**다른 컴퓨터에 복원:** 백업 가져오기 → Codex Manager로 만든 백업 폴더 선택 → 이 백업 복원하기 → 저장할 위치 선택.

**단축키:** Ctrl+F 검색, F5 새로고침, Alt+← 뒤로. 오른쪽 아래 **사용 안내**에서도 기본 흐름을 볼 수 있습니다.

프로젝트를 불러오면 모든 연결 폴더의 용량을 자동 계산합니다. 계산 중에도 프로그램을 사용할 수 있고, 완료 후 기본적으로 **용량 큰 순**으로 정렬합니다. **이름 순·용량 작은 순**도 선택할 수 있습니다. 새로고침하면 다시 계산합니다. 표시 값은 파일 크기의 합계이며 실제 디스크 할당량과 다를 수 있습니다. 연결 폴더·클라우드 자리표시자·읽을 수 없는 항목은 따라가지 않고 ‘일부 제외’ 또는 ‘확인 필요’로 표시합니다.

## 여러 저장소

시작 후 기본 Codex 경로, 이전에 등록한 위치, 로컬 드라이브에서 저장소를 자동으로 찾아 등록합니다. 왼쪽 저장소 목록에서 전환하면 각 저장소의 프로젝트와 대화를 볼 수 있습니다. 경로를 바꿔도 기존 등록 위치와 연결되지 않은 외장 저장소를 유지합니다. 서로 다른 저장소의 데이터베이스를 합치지 않습니다.

**다른 위치 찾기**에서 경로와 프로젝트·대화 수를 확인하고 **이 저장소 사용**을 누릅니다. **폴더 추가**는 정확한 Codex 저장소를 등록하며, **추가 검색 위치**는 선택한 상위 폴더에서 옛 저장소를 검색합니다. 프로젝트 안의 설정용 `.codex` 폴더는 대화 저장소가 없으면 등록하지 않습니다. 자동 검색은 깊이 5단계·12,000개 폴더로 제한하고 연결 폴더·AppData·의존성·테스트 산출물을 제외합니다. 범위 밖 위치는 추가 검색 위치로 지정하세요.

## 폴더 기준 대화 표시

이전 Codex 대화에는 명시적인 프로젝트 소속이 없는 기록이 있습니다. 작업 경로가 프로젝트 폴더와 일치하면 그 프로젝트 아래에 **폴더 기준**으로 표시합니다. 가장 가까운 폴더를 사용하며, 프로젝트 없는 대화로 지정된 기록과 다른 호스트의 대화는 자동 분류하지 않습니다. 부모와 폴더가 서로 다른 프로젝트를 가리키거나 여러 프로젝트가 같은 폴더를 쓰면 연결 확인 대상으로 남깁니다. 현재 프로젝트와 맞지 않는 옛 경로는 이유를 표시합니다.

폴더 기준 대화도 백업에 포함합니다. 실제 소속 정보는 원본 그대로 보존합니다. **대화 연결 확인**을 누르면 미리보기 후 프로젝트 소속을 저장합니다. 이동·합치기는 확인 화면에서 안내한 대화를 연결한 다음 이어서 실행합니다. 원본 정리는 연결 확인 후 사용하고, 원본 정리에는 확정 이후의 새 백업이 필요합니다. 프로젝트 밖 작업 폴더를 가진 자식 대화는 외부 의존성을 표시하며 해당 파일을 포함하지 않은 상태로 가져오기·정리하지 않습니다.

Codex 앱이 열려 있을 때는 조회와 백업을 사용할 수 있습니다. 연결을 변경하거나 가져오려면 Codex 앱을 완전히 종료하고 이 프로그램에서 실행한 뒤 Codex를 다시 여세요. 현재 Windows 앱 서버는 외부 프로그램이 기존 연결을 공유할 수 있는 daemon/proxy 경로를 제공하지 않아 이렇게 처리합니다. 대화가 다른 작업에서 실행 중이면 완료한 뒤 백업하세요.

## 옮기기·합치기

옮기기는 파일을 검증하고 대화의 현재 경로와 프로젝트 연결을 바꿉니다. 실행 확인 화면의 ‘원본 폴더 정리’를 선택하면 검증한 원본 파일을 제거합니다. 선택하지 않으면 원본 파일도 남습니다. 대화는 삭제하지 않습니다.

합치기는 A의 파일을 기본적으로 `B/A 이름/`에 넣고 A의 대화를 B에 연결합니다. 기존 B 파일을 덮어쓰지 않습니다. 파일 충돌이 있으면 자동 덮어쓰기 없이 중단합니다. Git 이력 병합 기능은 아닙니다.

변경 전 대화 복구 사본은 대상 프로젝트 바깥의 `.project-manager-recovery`에 보관합니다. 이 사본은 원본 폴더 정리와 별도로 남습니다.

## 다른 컴퓨터로 옮기기

1. 원래 컴퓨터에서 프로젝트를 ‘백업’하고 외장하드에 만든 백업 폴더 전체를 보관합니다.
2. 다른 컴퓨터에 Codex와 이 프로그램을 준비합니다. Codex에 로그인한 뒤 앱을 종료합니다.
3. ‘백업 가져오기’에서 `manifest.json`이 있는 폴더를 선택하고 복원할 위치를 지정합니다.
4. Codex를 열어 복원된 대화를 한 번 이어 사용합니다.
5. 이 프로그램의 백업 보관함에서 ‘복원 후 이어쓰기 확인’을 실행합니다. 성공 기록이 외장하드의 백업에 저장됩니다.
6. 원래 컴퓨터에서 같은 백업 폴더를 열고 원래 프로젝트를 선택하면 ‘백업 후 정리’를 사용할 수 있습니다. Codex를 종료하고 실행하면 원본 대화와 파일을 정리합니다.

대상 컴퓨터에 같은 ID의 대화가 이미 있으면 기존 대화를 덮어쓰지 않습니다. 실패한 가져오기는 ‘진행·복구’에서 이어서 실행할 수 있습니다. 이미 완료한 백업을 다시 같은 컴퓨터에 가져오는 기능은 현재 중복 충돌로 안내합니다.

## 백업 내용

`manifest.json`, `files/`, `conversations/`, `checksums.jsonl`, `verification.json`을 한 폴더에 보관합니다. 원래 드라이브 문자와 사용자 이름으로 복원할 필요가 없습니다. 폴더 전체를 복사하면 다른 컴퓨터에서도 프로그램의 기존 목록 없이 열 수 있습니다. 인증 토큰과 계정 설정은 포함하지 않습니다. 작업 폴더에 있는 `.env` 등의 사용자 파일은 포함됩니다.

## 확인이 필요한 경우

- 링크/junction 또는 클라우드 자리표시자는 범위 밖 파일을 자동으로 따라가지 않습니다. 일반 폴더에 자료를 준비하거나 연결 범위를 먼저 정리하세요.
- 여러 프로젝트가 공유하는 폴더, 다른 프로젝트 소속의 자식 대화, 연결된 worktree·외부 첨부는 자동 삭제 대상에서 제외됩니다. 미해결 의존성이 있으면 가져오기를 차단합니다.
- Codex 첨부 메타데이터가 있는 대화는 백업에 그 정보를 기록하되, 첨부 재등록까지 지원하지 않아 가져오기와 원본 정리를 차단합니다.
- 이동·복사 중 변경된 파일, 부족한 공간, 손상된 백업은 성공으로 표시하지 않습니다.
- 모바일의 연결 호스트에서 프로젝트 소속이 갱신됐는지는 실제 모바일에서 확인해야 합니다. 프로그램은 ‘모바일 미확인’으로 표시합니다.
- 이 프로그램은 로컬 Codex 대화를 지원합니다. ChatGPT 클라우드 대화를 내보내거나 삭제하는 기능은 없습니다.

실패한 작업은 ‘진행·복구’에서 원래 연결로 복구하거나 가져오기를 재개할 수 있습니다. 백업 후 원본 정리가 일부만 진행됐다면 검증된 백업에서 삭제된 대화와 파일을 복구합니다. 남아 있는 대화와 변경된 파일은 보존합니다. 복사본이 변경돼 자동 복구할 수 없으면 복구 사본의 경로와 오류를 확인하세요. 미완성 백업은 삭제 완료로 표시되지 않습니다.

외장하드를 분리해도 백업 보관함의 경로를 유지합니다. 설정 파일이 손상됐다면 원본을 별도 사본으로 보존한 뒤 설정을 다시 저장합니다. 같은 설정 폴더를 사용하는 프로그램을 중복 실행하지 않습니다.

외장하드 문자가 바뀌면 복구 화면에서 같은 백업의 새 위치를 선택할 수 있습니다. 프로그램은 bundle_id와 매니페스트 해시를 확인하므로 다른 백업으로 바꿔 이어 실행하지 않습니다. 작업을 시작한 Codex 저장소에서 복구하세요.

## 현재 검증 범위

Codex 앱 내장 CLI 0.160.0에서 격리 저장소 테스트와 실제 test b 대화의 복사본 복원을 확인했습니다. 실제 원본 test a/test b는 변경하지 않았습니다. 두 번째 물리 PC와 모바일 검수는 아직 수행하지 않았습니다. 원본 정리 테스트는 폐기 가능한 테스트 저장소에서만 수행했습니다.


v0.5.1: 일반 대화 목록에서는 보조 에이전트·자동 검토 기록을 기본적으로 숨깁니다. 상단의 `내부 작업 기록 포함`을 켜면 볼 수 있습니다. 내부 기록은 삭제되지 않으며 프로젝트 백업에는 계속 포함됩니다. 보조 에이전트는 이전 작업 폴더보다 기록된 원래 대화의 프로젝트를 우선해 표시하며, 실제 Codex 연결 변경은 기존 확인 절차를 따릅니다.


## v0.6.0 이름과 대화 정리

- 프로젝트를 선택하고 상단 **이름 변경** 또는 F2를 누릅니다. 실제 폴더명·경로는 그대로 유지됩니다.
- **모든 대화**에서는 제목·프로젝트·폴더 경로를 검색합니다. 전체/보관하지 않은/보관된 대화와 정렬 순서를 선택할 수 있습니다. 프로젝트 오른쪽 검색창은 해당 프로젝트의 대화를 찾습니다.
- Ctrl·Shift로 여러 대화를 선택하고 오른쪽 **제목 변경**을 누르면 앞/뒤 문구 추가와 문자열 바꾸기를 사용할 수 있습니다. 변경 전후 표를 확인한 뒤 적용합니다.
- 완료되었거나 중단된 제목 변경은 **작업 복구 → 제목 변경 되돌리기**에서 복원합니다. 이후 별도로 수정한 제목은 덮어쓰지 않습니다.
- **대화 관리 → 프로젝트로 이동**은 대화 소속만 바꿉니다. 프로젝트의 **옮기기/합치기**는 파일과 대화 작업 경로도 함께 옮깁니다. 대상은 이름 또는 폴더 경로로 검색할 수 있습니다.
- Ctrl+A는 현재 보이는 목록만 선택합니다. F2는 선택한 이름 변경, Delete는 삭제 확인을 엽니다. 실제 작업 파일 삭제는 기본 해제되어 있습니다.
- 백업 화면의 대화는 읽기 전용입니다. 화면의 검색·필터·내부 기록 숨김은 프로젝트 백업 범위를 줄이지 않습니다.
- 프로젝트 변경은 Codex 앱 종료 후 적용하도록 기존 보호 절차를 유지합니다. 모바일 표시 반영은 이 릴리스의 검증 범위에 포함되지 않습니다.


## v0.7.0 기본 단축키

목록을 클릭한 뒤 사용합니다. 검색창·이름 입력창에서는 일반 텍스트 편집 단축키가 동작합니다. 하단 **단축키** 버튼에서도 도움말을 볼 수 있습니다.

| 단축키 | 파일 목록 | 프로젝트·대화 목록 |
|---|---|---|
| Ctrl+C | 파일 복사 준비 | 이름과 프로젝트 경로를 텍스트로 복사 |
| Ctrl+X → Ctrl+V | 현재 폴더로 파일 이동 | 대상 프로젝트로 대화 소속 이동 / 프로젝트 합치기 확인 |
| Ctrl+V | 현재 폴더에 붙여넣기 (탐색기에서 복사한 파일도 지원) | 선택한 프로젝트 폴더에 파일 붙여넣기 |
| Delete | 복구 보관소로 파일 이동 | 프로젝트·대화 삭제 확인 |
| F2 | 파일·폴더 이름 변경 | 프로젝트 이름 / 선택한 대화 제목 변경 |
| Ctrl+Z | 최근 복구 가능한 작업 되돌리기 확인 | 동일 |
| Ctrl+A | 현재 목록 전체 선택 | 현재 목록 전체 선택 |
| Enter | 파일·폴더 열기 | 프로젝트 또는 대화 열기 |
| Esc | 잘라내기 취소 | 잘라내기 취소 |

Ctrl+F 검색, F5 새로고침, Alt+왼쪽 뒤로가기도 지원합니다. 프로젝트·대화 Ctrl+C는 전체 복제 기능이 아닙니다. 전체 자료를 보관하려면 백업을 사용하세요. 프로젝트 잘라내기·붙여넣기는 기존 병합 흐름으로 연결되며, 실제 원본 정리 여부는 확인 화면에서 선택합니다.

잘라내기만으로 원본을 변경하지 않습니다. 같은 이름의 파일은 복사본 이름을 붙여 보존합니다. 프로젝트 루트나 대화 작업 경로를 포함한 폴더는 일반 파일 단축키로 이동·삭제하지 않으며 프로젝트 옮기기/합치기를 사용해야 합니다. Codex 기록 변경은 Codex 앱 종료 후 적용하는 보호 절차를 유지합니다.

**파일 삭제, 복사 실행 취소, 중단된 복사 사본은 프로젝트 안의 `.codex-manager-file-recovery`에 보관됩니다. 디스크 공간은 즉시 확보되지 않습니다.** 이 보관소를 수동으로 정리하면 해당 파일 작업을 복구하지 못할 수 있습니다. 실행 취소는 파일 내용과 파일 식별 정보를 확인하며 이후 변경된 파일을 덮어쓰지 않습니다. 다른 드라이브로 이동할 때도 원본 복구 사본을 보존합니다. 다시 실행(Ctrl+Y)은 지원하지 않습니다.

- 작업표시줄 로고 경로와 재실행 정보를 Windows 창에 명시합니다. 로고 그림 자체는 기존 승인한 로고를 유지합니다.

## v0.9.0 프로젝트 트리와 작업 내역

- **왼쪽 프로젝트 트리**는 파일·대화 화면에서도 계속 보입니다. 프로젝트를 클릭하면 파일을 열고, 펼치면 등록된 폴더 위치를 선택할 수 있습니다. 트리의 검색창으로 이름·경로를 찾고, 우클릭 또는 별 버튼으로 즐겨찾기를 추가합니다. 즐겨찾기는 Codex 저장소별로 기억합니다.
- 여러 대화·프로젝트를 **왼쪽 대상 프로젝트에 바로 끌어 놓기**로 옮깁니다. 파일은 프로젝트 아래 등록된 폴더에도 놓을 수 있습니다. 실제 적용 전 대상과 변경 내용을 확인합니다.
- **선택 작업바**는 마지막으로 고른 목록에 맞춰 바뀝니다. 프로젝트는 옮기기·합치기·백업, 대화는 이동·제목 변경·삭제, 파일은 복사·잘라내기·붙여넣기·삭제를 제공합니다. 폴더를 바꾸거나 대화 탭을 숨기면 보이지 않는 항목의 작업 버튼도 해제됩니다.
- **프로젝트 여러 개를 선택 → 백업**으로 한 번에 보관합니다. 각 프로젝트의 파일·대화를 별도 백업 폴더에 복사하고 검증합니다. 같은 이름의 백업을 덮어쓰지 않습니다. 검증에 성공한 항목만 백업 목록에 등록하며, 실패한 부분 사본과 원본은 유지합니다.
- **작업 내역 · 복구**는 현재 Codex 저장소의 최근 200개 작업을 표시합니다. 항목별 완료·실패·미실행, 이전 위치와 이후/예정 위치, 오류를 확인하고 완료한 대상 폴더를 열 수 있습니다. 파일 작업·제목 변경·삭제 등 복구 가능한 작업에만 복구 버튼이 켜집니다.
- **미완료 항목 다시 시도**는 완료한 항목을 제외합니다. 먼저 중단된 변경을 복구해야 하는 경우에는 복구 버튼을 사용합니다. 재시도할 때 현재 프로젝트와 저장 위치를 다시 확인하며 원래 대상의 부분 파일을 덮어쓰지 않습니다. 이미 재시도한 이력에서는 최신 이력을 확인합니다.
- 작업 시작 전 계획과 각 항목의 결과를 저장합니다. 실행 도중 종료돼도 이전 완료 항목을 구분하고, 파일 이동 완료 직후 결과 저장 전에 종료된 경우에는 개별 작업 기록과 대조합니다. 백업 검증이 끝난 뒤 종료된 경우에는 백업에 저장한 완료 증거로 목록을 복원합니다. 백업을 실제로 복원할 때는 파일을 다시 검증합니다.
- 합치면 **대상 프로젝트 이름을 유지**하고 원래 프로젝트 이름은 프로젝트 목록에서 사라집니다. 대화는 대상에 모이고 파일은 각 원래 프로젝트 이름의 하위 폴더에 담습니다. 완료한 이동·합치기 전체를 자동으로 되돌리는 기능은 제공하지 않습니다.

실제 Codex 변경은 앱 종료 후 진행하는 기존 보호 절차를 따릅니다. 이 버전의 자동 검수는 격리된 테스트 저장소에서 진행하며, 두 번째 물리 컴퓨터와 모바일 동기화는 별도 확인이 필요합니다.
